# 后端输出查看指南（FHE-API · CipherBridge）

> 适用：本机（Ubuntu 22.04，root）已按 `tools/start_services.sh` 起好全套服务。
> 配套阅读：`SETUP_LOG.md`（环境搭建与问题记录）、`docs/CipherBridge_API_MANUAL.md`（接口手册）。
> **结论先行**：后端日志写在文件 **`/tmp/fhe_api.log`**；tmux 会话 `api` 里**看不到**日志（输出已被重定向到文件）。

---

## 0. 一分钟速查

```bash
# ① 实时查看后端输出（先开一个终端窗口挂着）
tail -f /tmp/fhe_api.log

# ② 另开一个窗口，触发一次后端输出
curl -X POST http://127.0.0.1:3000/generate_keys \
  -H 'Content-Type: application/json' \
  -d '{"public_key":"0xDemoTrigger1"}'
# → 第 ① 个窗口会新增 3 行 “compressed public key size / ...”
```

## 1. 后端输出在哪里

| 项目 | 值 |
|---|---|
| 日志文件 | **`/tmp/fhe_api.log`** |
| 实时查看 | `tail -f /tmp/fhe_api.log` |
| 只看末尾 | `tail -n 20 /tmp/fhe_api.log` |
| 进程会话 | tmux 会话名 `api`（**只用于确认进程存活/结束进程，不显示日志**） |

**为什么 `tmux attach -t api` 里是空的？**
启动脚本把后端输出重定向进了文件（见 `tools/start_services.sh` 第 54 行）：

```bash
tmux new -d -s api "cd '/root/Bisai/FHE-API' && cargo run --release > /tmp/fhe_api.log 2>&1"
```

所以日志只会进 `/tmp/fhe_api.log`，不会显示在 tmux 面板里。
（想让 tmux 里也能实时看到，见第 7 节「可选增强 B」。）

---

## 2. 怎么触发后端输出

后端源码里**只有两处**会打印内容，其它接口都很"安静"：

| 触发点 | 位置 | 输出内容 |
|---|---|---|
| 服务启动 | `FHE-API/src/main.rs` 第 38 行 | `Server running on http://0.0.0.0:3000` |
| `POST /generate_keys` | `FHE-API/src/main.rs` 第 61~72 行 | 3 行密钥大小（见第 3 节） |

> ⚠️ 后端**没有**请求日志中间件（`tracing-subscriber` 未初始化，也没有 `tower-http` 的 `TraceLayer`）。
> 因此调用 `/get_public_key`、`/encrypt`、`/compute`、`/decrypt` **不会产生任何新输出**。
> **唯一能触发业务输出的接口是 `/generate_keys`。**

### 触发方式（任选其一）

```bash
# ① 直连后端（推荐，最直观）
curl -X POST http://127.0.0.1:3000/generate_keys \
  -H 'Content-Type: application/json' \
  -d '{"public_key":"0xDemoTrigger1"}'

# ② 经前端 vite 代理（等价；前端 :5173，代理 /service → :3000）
curl -X POST http://127.0.0.1:5173/service/generate_keys \
  -H 'Content-Type: application/json' \
  -d '{"public_key":"0xDemoTrigger1"}'

# ③ 浏览器 UI：打开 http://localhost:5173 → Client Portal → 点 “Generate FHE Keys”
```

> ⚠️ **务必用一个全新的临时 `public_key`**（如 `0xDemoTrigger1`）。
> 源码里 `generate_keys` 会对同一个 `public_key` **覆盖旧密钥**（见 API 手册第 12 节已知问题 4）。
> 若用某个真实用户/钱包地址触发，会把该用户已生成的 FHE 密钥冲掉，导致其旧密文再也解不开。

> 提示：`/generate_keys` 的响应体很大（约 **36MB**，含 fhe_public_key/server_key/client_key 三个 base64 串）。
> 不要直接在终端里 `curl ...` 打印响应，用 `-o /dev/null` 或 `-o /tmp/resp.json` 丢掉/落盘。

## 3. 输出长什么样

**启动时**（服务刚起来，日志开头）：

```text
Server running on http://0.0.0.0:3000
```

**每次调用 `/generate_keys` 后**，末尾新增 3 行：

```text
compressed public key size  : 16524
compressed server key size  : 27410659
client key size            : 23254
```

> 其中 `compressed server key size` 特别大（约 27MB），这是因为 TFHE 的 server key 需要支持同态运算。

## 4. 完整操作流程（照抄即可）

```bash
# Step 1. 确认后端在跑（应看到 :3000 LISTEN 和 tfhe-example 进程）
ss -lntp | grep ':3000'

# Step 2. 开一个窗口，实时跟踪日志
tail -f /tmp/fhe_api.log

# Step 3. 另开一个窗口，触发一次输出（用新 public_key，响应丢弃）
curl -s -o /dev/null -X POST http://127.0.0.1:3000/generate_keys \
  -H 'Content-Type: application/json' \
  -d '{"public_key":"0xDemoTrigger1"}'

# Step 4. 回到 Step 2 的窗口，应看到新增 3 行 “... size : ...”

# Step 5. 退出 tail：按 Ctrl+C
```

**不实时跟踪、事后查看**也可以：

```bash
# 触发
curl -s -o /dev/null -X POST http://127.0.0.1:3000/generate_keys \
  -H 'Content-Type: application/json' -d '{"public_key":"0xDemoTrigger2"}'
# 事后看最后几行
tail -n 6 /tmp/fhe_api.log
```

## 6. 常见问题（FAQ）

| 现象 | 原因 / 处理 |
|---|---|
| `tail -f` 没任何反应 | 你调的很可能是 `/encrypt`、`/compute`、`/decrypt`——后端这几条**不打日志**。请改调 `/generate_keys`。 |
| `tmux attach -t api` 里一片空白 | 正常。输出已重定向到 `/tmp/fhe_api.log`，请用 `tail -f` 看文件。 |
| 日志里没看到“请求”记录 | 后端没有请求日志中间件，属当前设计；需要的话见第 7 节 A。 |
| `curl` 卡住 / 终端刷屏乱码 | `/generate_keys` 响应约 36MB，请加 `-o /dev/null` 丢弃响应体。 |
| `tail` 里出现 `warning: unused import: get` | 这是编译期 warning（只出现在首次 `cargo run` 时），不影响运行。 |
| 想看更早的输出（服务重启前的） | 日志文件在每次 `start_services.sh` 时会被覆盖（`> /tmp/fhe_api.log`），历史已丢。 |
| 日志文件太大 | `: > /tmp/fhe_api.log` 可清空（不影响正在运行的进程写入）。 |

## 7. 可选增强（需要我改代码/脚本时，告诉我即可）

### A. 让后端打出“每个请求”的日志（含 `/encrypt`、`/compute`、`/decrypt`）
在 `FHE-API/src/main.rs` 里：
1. `main()` 开头加 `tracing_subscriber::fmt::init();`
2. 路由上挂一层中间件 `.layer(tower_http::trace::TraceLayer::new_for_http())`

依赖已在 `Cargo.toml` 中，但需**补开 `trace` feature**（当前只开了 `limit`）：

```toml
tower-http = { version = "0.4", features = ["limit", "trace"] }
```

→ 之后每次请求都会打印路径/状态码/耗时。

### B. 让 tmux 会话里也能实时看到后端输出
把 `tools/start_services.sh` 第 54 行改为用 `tee`：

```bash
tmux new -d -s api "cd '/root/Bisai/FHE-API' && cargo run --release 2>&1 | tee /tmp/fhe_api.log"
```

→ 这样既能 `tail -f /tmp/fhe_api.log`，也能 `tmux attach -t api` 直接看。
